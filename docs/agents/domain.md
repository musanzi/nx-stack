# Domain docs

This repository uses a single-context layout across the API, web app, and shared API contracts.

## Before exploring

- Read `GLOSSARY.md` at the repository root if it exists.
- Read decisions in root `docs/adr/` that concern the area under investigation.

If these files are absent, proceed silently.
Create them through domain modeling when terms or decisions are resolved.

## File locations

- `GLOSSARY.md` holds the shared domain vocabulary.
- `docs/adr/` holds architectural decision records.

## Use the glossary's vocabulary

Use defined domain terms in issue titles, proposals, hypotheses, and tests.
Follow any explicit guidance about synonyms.

If a needed concept is missing, check existing project terminology.
Record a real vocabulary gap for domain modeling.

## Flag conflicts with decisions

If a proposal contradicts an existing ADR, identify the ADR and explain
why the decision needs reconsideration before overriding it.
